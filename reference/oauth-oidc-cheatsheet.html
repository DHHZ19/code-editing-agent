Quick reference · OAuth + OIDC

Who proves what?

Keep the protocol, tokens, and local app session distinct.

ThingWhat it meansTrust / use
OAuth 2.0Delegated authorization: a client gets scoped access to a resource.Not, by itself, a login or identity protocol.
OpenID Connect (OIDC)An identity layer on OAuth 2.0. The openid scope requests authentication.Defines the ID token and identity claims.
Authorization codeShort-lived, one-time credential delivered to the registered redirect URI.Exchange at the token endpoint; it is not an access token.
ID tokenSigned JWT assertion from the issuer about an authentication event and subject.Validate signature, issuer, audience, expiry, and nonce if sent. Intended for the OIDC client.
Access tokenCredential for calling a protected resource with granted authority.Send to the intended API, not as proof of the user's identity to your app.
Refresh tokenCredential used at the authorization server to obtain new tokens.Highly sensitive; protect and rotate/revoke according to provider behavior.
App session cookieYour app's own browser credential, usually created after validating the OIDC response.Controls the user's session with your app; distinct from Google's tokens.
Remember: Google authenticates the person; OIDC conveys a verifiable identity assertion to the client; your app validates it and decides whether to establish its own session.

Authorization-code flow in one line

Browser → Google authorization endpoint → browser returns with code → client exchanges code (+ PKCE verifier) at token endpoint → client validates ID token → app creates local session.

Correlation / defenses: state binds the callback to the initiating browser request; PKCE binds the code exchange to the client instance that began it; nonce binds the ID token to the authentication request when used.
